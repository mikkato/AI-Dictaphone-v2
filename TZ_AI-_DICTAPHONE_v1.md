# ТЗ: Android-приложение «AI-диктофон / Протоколист совещаний» (v1.0)

Документ для кодинг-агента. Все требования обязательны, кроме явно помеченных «опционально (фаза 2)».

---

## 1. Общая информация

**Цель.** Приложение для Android (запуск на GrapheneOS), превращающее аудиозаписи совещаний и диалогов в текст и структурированные протоколы:

1. **Транскрипция — локально**, модель Whisper, файл модели скачивается с Hugging Face при первом запуске и хранится в папке приложения на телефоне.
2. **Суммаризация — внешней LLM** через OpenAI-совместимый API (`<base_url>/v1/chat/completions`), base URL и API-ключ задаются пользователем в настройках.
3. Источник аудио: **выбор готового файла (mp3/wav) из памяти телефона ИЛИ запись микрофоном** самим приложением.

**Референсы функционала** (изучены, объём v1 повторяет их ключевые возможности, без облачной синхронизации и без агентных фич):
- **PLAUD (plaud.ai)**: транскрипция с таймстампами, метки спикеров, кастомная лексика, подсветка ключевых моментов (highlights), текстовые заметки и изображения в контексте записи, шаблоны саммари (в т.ч. пользовательские), поиск по всем заметкам, экспорт во многие форматы, переход по клику из транскрипта в позицию аудио.
- **Samsung Notes / Voice Recorder (Galaxy AI Transcript Assist, One UI 7–8)**: вкладки «Transcript / Summary» внутри записи, распознавание спикеров, перевод, стили саммари (Standard / Detailed), порог минимальной длины для саммаризации, «Add to Notes», прикрепление записи с транскриптом к заметке.

**Целевое устройство:** Google Pixel 10 Pro, 128 ГБ, GrapheneOS (Android 16 / API 36). Сохранение совместимости с широким ARM64 не требуется — оптимизируем под этот device profile, но **minSdk = 35** (Android 15), **targetSdk = 36**.

## 2. Технологический стек (обязателен)

- **Kotlin 2.x, Jetpack Compose + Material 3**, MVVM + Coroutines/Flow, один модуль приложения + нативный C++ слой.
- **ASR: whisper.cpp**, собран через **NDK r27+ / CMake**, обёртка JNI. Поддерживаемые форматы модели — `.bin` (GGML v3).
- **Диаризация (опц., фаза 2): sherpa-onnx** (AAR `com.k2fsa.sherpa.onnx`, с готовым arm64-таргетом) — Silero VAD + speaker embeddings (3D-Speaker CAM++) + агломеративная кластеризация.
- **Декодирование аудио: Android MediaCodec** (mp3 → PCM), свой парсер WAV. **Никакого ffmpeg.**
- БД: **Room** (+ FTS5 для поиска). Сеть: **OkHttp** (включая SSE для streaming-ответов LLM). Хранение настроек/ключей: **EncryptedSharedPreferences** (Android Keystore). Фоновые задачи: **WorkManager**.
- Разрешения: `RECORD_AUDIO`, `READ_MEDIA_AUDIO`, `POST_NOTIFICATIONS`, `INTERNET`, `WAKE_LOCK`, `FOREGROUND_SERVICE` (+ типы сервисов `foreground-service-microphone` для записи, `foreground-service-data-sync` для транскрипции).
- UI-язык интерфейса: **русский** (строки в `strings.xml`, подготовка к локализации).

**⚠ Known pitfall (обязательно учесть):** на чипах Google Tensor исторически падают сборки llama.cpp/whisper.cpp, скомпилированные с `-march=armv8.2-a+dotprod+i8mm` (illegal instruction). Собирать с **runtime-детектом CPU-фич** (`__ARM_FEATURE_DOTPROD`/`__ARM_FEATURE_MATMUL_INT8` включать только если реально поддержаны) и при первом запуске выполнять сам-тест декодирования 1-секундного синтетического звука; при illegal instruction — fallback-сборка без dotprod/i8mm. Не гадать — заложить в код.

## 3. Модель Whisper: скачивание и хранение

- Реестр моделей в настройках (публичные, **без HF-токена**, проверено 03.11.2026, репозиторий `ggerganov/whisper.cpp` на huggingface.co):

| Модель | Файл | Размер | Роль |
|---|---|---|---|
| large-v3-turbo (f16) | `ggml-large-v3-turbo.bin` | 1 624 555 275 Б (~1.6 ГБ) | **по умолчанию**, лучшее качество RU |
| large-v3-turbo q8_0 | `ggml-large-v3-turbo-q8_0.bin` | 874 188 075 Б (~874 МБ) | лёгкая альтернатива |
| large-v3-turbo q5_0 | `ggml-large-v3-turbo-q5_0.bin` | 574 041 195 Б (~574 МБ) | минимальная |

  URL: `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/<file>`
- **При первом запуске** — экран «Скачать модель»: выбор версии, показ размера, прогресс с возобновлением (HTTP Range), проверка контрольной суммы (SHA-256 вычислить и зафиксировать в коде при скачивании эталонного файла на этапе разработки), отмена.
- Хранение: `getExternalFilesDir(null)/models/`. Пользователь может указать и **свой путь/файл** (SAF-picker) — модель должна читаться из выбранной папки без повторного скачивания (поддержка уже лежащей на телефоне модели).
- Недоступный хост — поле «свой URL» в настройках (для зеркала).

## 4. Экраны и пользовательские сценарии

### 4.1 Библиотека записей (главный экран)
- Список «заметок»: название (автоимя из даты/первой фразы), длительность, статус: `аудио → транскрибируется → транскрипт → готово` (ошибки отдельно), превью саммари, дата, теги.
- Кнопки: «Импорт аудио» (SAF, `audio/mpeg`+`audio/wav`+все расширения `.mp3/.wav`), «Запись» (микрофон).
- Поиск (FTS5 по транскриптам, саммари, заметкам) и фильтр по статусу/тегам.
- Свайп-действия: удалить, пере-транскрибировать, пере-саммаризировать, экспорт,share.

### 4.2 Запись микрофоном
- Экран с уровнем (_live meter_), таймером, пауза/продолжить; запись через `AudioRecord`, PCM → сохранение **WAV 16-бит mono 48 кГц** (Whisper-даунсемплинг делает сам).
- Запись — **Foreground Service** с нотификацией (пауза/стоп из нотификации).
- Во время записи — кнопка «Highlight» (отмечает текущий момент, см. 4.4) и поле быстрой текстовой заметки с автосохранением по времени (как текстовые заметки/хайлайты в моменте у PLAUD).

### 4.3 Импорт файла
- Выбор mp3/wav из памяти; копирование в приватное хранилище приложения; сразу — создание заметки и постановка транскрипции в очередь.
- Валидация: понятная ошибка для неподдерживаемого контейнера; ограничение длительности — предупреждение после 3 часов (как лимит Samsung Transcript Assist), не блокировка.

### 4.4 Карточка записи (ядро продукта — аналог PLAUD/Samsung)
- **Аудиоплеер** поверх контента: **Player-view на androidx.media3 ExoPlayer** (скорость 0.75–2× со встроенным сохранением тона — эквивалент SoundTouch у PLAUD), waveform-подобная шкала (достаточно сегментной по времени), перемотка ±10 с.
- **Вкладка «Транскрипт»**: сегменты с таймстампами `[мм:сс]` и **метками спикеров** «Спикер 1/2/…» (если диаризация включена); **клик по сегменту — перемотка аудио** к этому моменту; редактирование текста сегмента и переименование спикера (переименование применяется ко всем сегментам); подсветка сегмента, играющего в данный момент.
- **Вкладка «Саммари»**: результат LLM (см. §6) с выбором стиля **Standard / Detailed** (по образцу Samsung) и шаблона; история перегенераций; кнопка «Заново».
- **Вкладка «Заметки»** (опц., фаза 2): текстовые заметки и изображения, прикреплённые к записи (из §4.2 и из галереи) — идут в контекст саммари как подписанный текст; картинки передаются LLM только если в настройках отмечена поддержка vision текущей моделью, иначе их описание-заглушка не выдумывается — передаётся только текст заметок.
- **Highlights**: список моментов (время + подпись), клик — перемотка; передаются в контекст LLM как «ключевые моменты, отмеченные пользователем».
- **Экспорт** (Share Sheet): `.txt` (текст с авторами/временем), `.md`, `.srt`, `.json` (полная структура). Копирование в буфер всего транскрипта/саммари.

### 4.5 Настройки
- **LLM**: base URL (поле оканчивается на `/v1` автоматически, если не указано), API-ключ (скрытое поле, проверка «тест соединения» — GET `/v1/models` или минимальный chat request), имя модели, temperature (0–1, default 0.3), max_tokens, лимит символов на чанк саммаризации (default 8000).
- **Whisper**: выбранная модель, язык (`auto/ru/en/by-language picker`, по умолчанию auto с приоритетом RU), «кастомная лексика» (список терминов → передаётся в `initial_prompt` whisper.cpp — реальный механизм, не выдумывать), число потоков inference (default = физических ядер/2).
- **Диаризация**: вкл/выкл (default выкл до фазы 2), ожидаемое число спикеров (2–6, подсказка кластеризации).
- **Модель**: список скачанных моделей, размер, удалить, скачать другую.

## 5. Пайплайн транскрипции (обязательные детали)

1. **Декодирование в PCM 16 кГц mono float32**:
   - WAV: свой парсер (RIFF/PCM 16/24-бит, mono/stereo → микс в mono, ресемплинг к 16 кГц линейной интерполяцией; при отклонении >1% длительности заголовка — ресемплинг по факту).
   - MP3: MediaCodec-декодер → PCM → ресемплинг к 16 кГц. Ошибка декода — понятная ошибка в UI, не падение.
2. **Whisper inference**: `whisper_full` c параметрами: `word_timestamps=true` (для под-сегментной подсветки, опц.), `thread` из настроек, `language` из настроек (`auto` → VAD-автодетект), `no_speech` фильтр. Сегментация — по таймстампам whisper (окна ~5–12 с).
3. Прогресс — реальный процент по фреймам (`progress_callback`) в нотификации и на карточке; задача в **WorkManager**, отменяемая, переживает перезапуск приложения (входящие в очередь — `ENQUEUED`, возобновление с чанка, не с начала всей записи — чанкование аудио по 10-минутным окнам с перекрытием 2 с и сшивкой сегментов по времени).
4. Результат → Room: сегменты `(start_ms, end_ms, speaker_id, text)`.
5. **Диаризация (фаза 2, если включена)**: поверх готовых сегментов — VAD-ембеддинги sherpa-onnx + кластеризация → присвоение `speaker_id`; переименование спикера пользователем не затирается при пере-запуске.

## 6. Суммаризация через внешний OpenAI-совместимый API

- Эндпоинт: `POST <base_url>/chat/completions`, заголовки `Authorization: Bearer <ключ>`, тело `{model, messages, temperature, max_tokens, stream:true}`.
- Промпт (system, рус.): «Ты — протоколист совещаний. Верни структурированное саммари: **Краткое резюме; Ключевые обсуждения; Решения; Задачи/обязанные (кто/что/срок); Открытые вопросы**». Стиль Detailed добавляет детализацию по каждому сегменту; выбор шаблона (совещание/интервью/звонок/лекция/пользовательский) подставляет свой system-промпт (редактируемые, хранятся локально).
- Контекст: транскрипт + хайлайты + текстовые заметки. **Длинные транскрипты**: разбивка на чанки ≤ лимита символов → саммари каждого (map) → финальное саммари из частичных (reduce). Это обязательное поведение, не опция.
- SSE-streaming с индикатором «печатается…»; частичный ответ сохраняется.
- **Порог минимума** (как Samsung): транскрипт < 200 символов → саммаризация не запускается, UI объясняет причину.
- Ошибки: 401 → «проверьте ключ», 404 → «проверьте имя модели», timeout/5xx → retry ×3 с экспоненциальной задержкой, затем понятная ошибка; сеть недоступна — кнопка «Повторить» позже, задача не теряется.
- Ключ API: только EncryptedSharedPreferences; **никогда не логировать**; экспорт заметки ключ не содержит.

## 7. Нефункциональные требования

- **Производительность**: целевой RTF транскрипции large-v3-turbo на Pixel 10 Pro ≤ 2× реального времени (замер на тестовом WAV 10 мин, RU; зафиксировать в отчёте разработки). UI не должен блокироваться ни на одной операции inference (все в фоновых корутинах/WorkManager).
- **Память**: inference под f16-модель ≤ 2.5 ГБ RSS; при OOM — автоматический ретрай с q8_0/q5_0 и предложение скачать её, если отсутствует.
- **Надёжность**: убитие процесса во время транскрипции → задача возобновляется; удаление заметки не трогает скачанную модель.
- **Приватность (GrapheneOS-этика)**: аудио и транскрипты не покидают устройство, кроме отправки текста в указанный пользователем LLM-API; в UI на экране настроек — прямое об этом сообщение.
- **Тесты**: unit-тесты парсера WAV, сшивки чанков, сборки промпта/map-reduce; instrumentation-тест импорта mp3→PCM;手ной чек-лист приёмки (п. 9) обязателен к прогону на реальном устройстве.

## 8. Что явно НЕ входит в v1 (не реализовывать)

Облачная синхронизация и аккаунты, экспорт DOCX/XLSX, «агент»/чат с заметкой (Ask-PLAUD), перевод транскрипта, автоматическое определение начала встречи, виджеты, WearOS, multi-device, платёжные функции, загрузка моделей из каталога внутри приложения (только фиксированный реестр + свой URL), обработка видео.

## 9. Критерии приёмки (проверяются на Pixel 10 Pro / GrapheneOS)

1. Первый запуск → скачивание `ggml-large-v3-turbo.bin` (~1.6 ГБ) с прогрессом, возобновляемое после обрыва; модель читается с указанного пользователем пути без повторного скачивания.
2. Импорт реального совещания mp3 20+ минут → транскрипт RU с таймстампами ≤ RTF 2×, клик по сегменту перемотывает плеер; редактирование сегмента сохраняется.
3. WAV 48 кГц stereo импортируется без ручных конвертаций; mp3 128 кbps — без артефактов рассинхрона > 1 с.
4. Запись микрофоном 10 мин с паузами/хайлайтами/текст-заметками → транскрипт, хайлайты кликабельны.
5. Саммари через тестовый OpenAI-совместимый endpoint: структура «Резюме/Обсуждения/Решения/Задачи/Вопросы», стили Standard/Detailed различимы, длинный транскрипт (>лимита) проходит map-reduce и не обрезается молча.
6. Диаризация (фаза 2) на записи 3 спикеров: корректное разделение ≥ 80% реплик на выборке; выключенная диаризация ничего не добавляет.
7. Экспорт `.txt/.md/.srt/.json` открывается в сторонних приложениях; Share отправляет файл.
8. 401/404/offline — сообщения соответствуют §6, ключ не светится в логах (`adb logcat` проверка).
9. Freeze/краш при inference на Tensor G5 отсутствует (сам-тест dotprod/i8mm из §2 выполнен).

## 10. Этапы сдачи

- **Фаза 1 (MVP)**: стек+модель (скачивание), импорт WAV/MP3, транскрипция фоновая, карточка «плеер+транскрипт», саммари через API (map-reduce), настройки, экспорт txt/md/srt/json, поиск базовый.
- **Фаза 2**: запись микрофоном (Foreground Service), хайлайты+заметки, шаблоны саммари + свои, поиск FTS5, экспорт JSON полный, редактирование спикеров.
- **Фаза 3 (опц.)**: диаризация sherpa-onnx, вкладки изображений/vision, история саммари.

Каждая фаза — рабочий APK, прогон §9 частично, отчёт с замерами.

## 11. Результаты реверс-инжиниринга PLAUD (APK v4.0, `ai.plaud.android.plaud`, 130 МБ, JADX/REA, 03.11.2026) — контекст для исполнителя

Факты, полученные разбором APK; влиять на реализацию should, где указано:

1. **PLAUD — Flutter-приложение** (libflutter.so + Dart-AOT libapp.so), не нативное. Native-слой: полный **FFmpeg** (libavcodec/avformat/avfilter/swresample) для конвертации аудио, **libmpg123** (декод mp3), **liblame** (кодирование mp3), **libopus + ogg** (формат записей устройства), **libsoundtouch** (изменение скорости воспроизведения с сохранением высоты тона).
   → Наше решение MediaCodec (mp3→PCM) остаётся в силе: у нас вход строго mp3/wav и своя запись WAV, полный FFmpeg (≈15 МБ .so) не нужен. Скорость воспроизведения с сохранением тона — через ExoPlayer PlaybackParameters (уже в §4.4).
2. **Транскрипция у PLAUD — облачная**: в APK нет ни whisper.so, ни sherpa, ни локальных STT-моделей; эндпоинты `https://api.plaud.ai` (+ dev/staging-зоны `api-*.plaud.ai`). Локально — только VAD: **WebRTC VAD** (`libvad_jni.so`, JNI `com_konovalov_vad_webrtc_VadWebRTC_nativeIsSpeech`, режимы/16 кГц) — используется для activity-detection, не для распознавания. Плюс `libonnxruntime.so` (27 МБ) + `libonnxruntime4j_jni.so` — ONNX-рантайм под клиентские ML-мелочи; и проприетарный аудио-DSP `libSoundPlus.so` (шумоподавление/AGC, «AGC_YL_*», mic array) и `liblpa.so` (OTA/обновления с cert pinning) — относятся к фирменному железу, к нашему приложению отношения не имеют.
   → Подтверждение архитектуры ТЗ: локальный ASR (Whisper) — наше отличие и преимущество (работает без облака); решение о локальной VAD в §5 оставить Whisper-штатной опцией. **Обязательное следствие:** раз у PLAUD диаризация тоже серверная (коллекции `SpeakerLabel/SpeakerLabelV2/cloudSpeakerId` заполняются из облака), наше решение «диаризация — опциональный локальный модуль, фаза 3» — технически смелое, но в рамках разумного; риск-фолбэк: при неудовлетворительном качестве на Tensor G5 диаризация остаётся отключённой фичей (заказчик согласовал: «желательно, но можно отключить»).
3. **Модель данных заметки у PLAUD** (изо-коллекции в Dart-снимке): `TranscriptionData`, `TranscriptionTaskConfig`, `SpeakerLabel`/`SpeakerLabelV2`/`SpeakerLabelOrigin` (версионируемые метки спикеров, облачный id + происхождение), `TemplateCacheEntity`/`TemplateSelectCacheEntity` (шаблоны саммари кэшируются локально), `MultimodalHighlightFinishedNote` (завершённые хайлайт-заметки).
   → Схема данных (§5.4) это покрывает; добавить в Room-сущность сегмента поле `speakerOrigin` (локальная диаризация | переименовано пользователем) — переименования пользователя не затираются при пере-запуске диаризации (требование §5, п. 5, фиксируем поле).
4. **Manifest-референс**: minSdk 29 / targetSdk 36; разрешения включают `RECORD_AUDIO`, `FOREGROUND_SERVICE` + типы `dataSync`/`mediaPlayback`, `POST_NOTIFICATIONS`, `WAKE_LOCK`, `SCHEDULE_EXACT_ALARM`, `READ_MEDIA_IMAGES/VIDEO`, Bluetooth-стек (для их устройства).
   → Берём наш набор из §2 (Bluetooth не нужен) + добавляем `WAKE_LOCK` и `FOREGROUND_SERVICE_MEDIA_PLAYBACK`/`DATA_SYNC` типы сервисов; `FOREGROUND_SERVICE_MICROPHONE` для сервиса записи (уже включён §4.2).
5. **UI-паттерны, подтверждённые кодом**: режим/стратегия подсветки транскрипта (`FocusHighlightMode/FocusHighlightStrategy` — синхронная подсветка сегмента при воспроизведении — реализовано в §4.4), локальный кэш шаблонов (§4.5 «шаблоны, хранятся локально»), облачная загрузка конфигурации API через componentConfig (`api.protocol/host/uploadPath`) — у нас роль выполняет §4.5 настройки LLM.

Что реверс **не** показал (проверено, отсутствует): локальный Whisper/CTranslate2, офлайн-режим транскрипции, локальные языковые модели — у PLAUD всё это на сервере. Ожидать от PLAUD офлайн-качества в нашем референсе ошибочно — наше ТЗ сознательно берёт это на себя локально.
